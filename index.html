How to use

Serve a folder, list its contents, write Markdown with --- between slides, open it. Commands below are examples you can adapt.

1. Serve a folder and list it

Each directory has a list.txt: one path per line, directories end with /. Hidden entries (starting with .) are skipped.

# serve the course folder over HTTP (any static server works)
cd ~/course
python3 -m http.server 8000

# one way to generate list.txt in every folder (dirs get a trailing /)
for d in . */; do (cd "$d" && ls -1p > list.txt); done

2. Write slides in Markdown

A line containing only --- starts a new slide. The first heading becomes the slide’s entry in the navigator. Math and code blocks are rendered and highlighted.

# Containers 101
What a container is, in one slide.

---

## Why Docker?
- Same environment everywhere
- Fast to start

---

## Run it
```bash
# start a container and remove it on exit
docker run --rm -it alpine sh
```

3. Navigate with the URL

The location is stored in the hash, so every view is linkable and the browser Back button works.

# folder + file in the hash
http://localhost:8000/#d=/week1/&f=intro.md

# folder only: shows the directory listing
http://localhost:8000/#d=/week1/

4. Open, present, print

# Open a local file (no server needed): footer "Open" button, Ctrl+O, or drag a file onto the page
#   supports .md  .markdown  .ipynb  .csv   (several files at once are opened in order)

# Present: press F for fullscreen, arrows / PageUp / PageDown to move
# Print:   "Print Slides" = one slide per page (save as PDF, no margins)
#          "Print Notes"  = compact pages for paper

Slides

Markdown decks with a searchable navigator, slide counters and a Source link.

Notebooks

Markdown cells, code inputs and outputs (text, streams, images) as blocks.

CSV tables

Header row plus a search box that filters rows as you type.

PDF & downloads

PDFs open in a dialog; docx, xlsx, pptx, odt, ods and odp download directly.

Functions

Every file type has a loader (gets the content and prepares the page) and a processor (turns content into DOM inside any target). Processors only clear the target in over mode, so they can be reused to add content anywhere.

// processors: content in, DOM out. target defaults to "#main", mode to MODE.over
const view = processMarkdown(mdText, { target: "#notes", mode: MODE.after });
// view = { root, nav, slides }

// loaders: URL or File in, calls the processor. Same options.
await loadMarkdown("/week1/intro.md", { callback: (v) => console.log(v.slides.length) });
await openSource(fileFromInput);   // picks the loader from the handlers registry

External helpers used by slidegen (not defined in it): gen, gens, append, grab, getfile, load, loadscss, parsemd, WebHelper.
